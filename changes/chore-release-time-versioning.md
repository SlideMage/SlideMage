Release-time versioning: a PR no longer bumps VERSION_NUMBER or appends to CHANGELOG.md, which made every two open PRs conflict. It adds a fragment to changes/ (kind fixed, new or breaking; reason; technical text; NEW: bullets; for breaking a BREAKING: paragraph and a compat: line), read and checked by the new slidemage.change_fragments (`python -m slidemage.change_fragments --check`). packaging/make_release.py collects the fragments, raises the last release by the biggest kind (0.x: breaking the minor, else the patch; from 1.0 major, minor, patch), appends one CHANGELOG entry for the release, sets VERSION_NUMBER, writes the version over since="NEXT" in compat*.py, deletes the fragments and, with --publish, merges a release/vX.Y.Z PR and tags it. compat.evaluate counts since="NEXT" as the running version, so a build from source applies an unreleased change. version.VERSION reads "v0.17.38+dev (commit, date)" while the checkout has fragments; the About sheet lists them on top as Unreleased. changelog-check.yml now fails a PR that changes the app without a fragment (label no-changes-entry to skip), that changes VERSION_NUMBER or adds a CHANGELOG entry outside a release/* branch, or whose fragments have problems; release.yml refuses a tag with fragments or NEXT left over. version.parse_news is public and parse_history() takes a text. CHANGELOG intro, README, the finish and handover skills follow. Tests in tests/test_change_fragments.py, tests/test_make_release.py, tests/test_version.py and tests/test_about_gui.py.

NEW: Versions are now set when a release is made, not by every change.
- Info, Version history lists one entry per release; a build from source shows the changes since the last release on top, as Unreleased.
- A build from source shows its version as the last release plus "+dev" and the commit.
